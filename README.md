# Flow Matching in higher dimensions using MuJoCo

The goal is to see how flow matching behaves in higher dimensions, tracked
through the explicit states of the MuJoCo simulator.

A flow-matching network (a residual MLP) learns to predict the next state
`[qpos, qvel]` of simulated MuJoCo worlds, mostly pendulums. It is scored on
one-step error and on 100-step rollouts where it runs on its own predictions.
Seventeen experiments compare setups, model choices, inputs and state sizes up to D = 1024.

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt     # video rendering also needs ffmpeg (brew install ffmpeg)
```

## Run

```bash
python -m experiments.run                                  # all 17 experiments, seeds 0 1 2 (348 runs, days; resumable)
python -m experiments.run --only setup collisions          # selected experiments
python -m experiments.run --quick --out /tmp/q --seeds 0   # tiny smoke test, under a minute
python -m experiments.run --set epochs=100                 # override any RunConfig field
python -m experiments.run --dry-run                        # list runs, train nothing
python -m experiments.report --out results                 # rebuild figures and REPORT.md only
python -m experiments.site                                 # refresh the website in docs/ from results/
```

Finished runs are skipped, so an interrupted sweep continues where it stopped (`--force` reruns).

Output in `results/`:

| Path | Contents |
|---|---|
| `REPORT.md` | one section per experiment: question, figure, table (mean ± 95% CI over seeds) |
| `figures/<experiment>.png` | the experiment's figure |
| `videos/<variant>.mp4` | true (left) vs predicted (right) 1-second rollout |
| `summary.json` | every number in the report, machine-readable |
| `runs/<variant>__seed<k>/` | `metrics.json` and `curves.npz` of one run |
| `datasets/` | cached simulated clips, shared between runs |

Only `REPORT.md`, `figures/` and `summary.json` are committed; the rest is
regenerated by `python -m experiments.run`.

## Website

`docs/` is the presentation page: charts, rollout videos and conclusions for
every experiment. `python -m experiments.site` refreshes its numbers
(`docs/data.js`) and videos from `results/`; the text is in `docs/index.html`.
It is a static page, so it can be served as is, e.g. by GitHub Pages from `/docs`.
Check it without a browser with `node scripts/check_site.js docs`.
Each week's page is also kept as a snapshot in `docs/weeks/week-NN/` (see `docs/weeks/README.md`).

## The 17 experiments

| Key | Question |
|---|---|
| `setup` | How much harder is the ground pendulum (rods fall onto a solid floor) than a freely hanging one? |
| `collisions` | In the ground setup, do predicted rods respect the floor, and are contact steps the hard part? |
| `size` | More separate pendulums vs one longer chain, hanging and on the ground: is it the size of the state or the coupling? |
| `design` | Flow matching vs plain regression, predicting the change vs the next state |
| `gravity` | When does telling the model the gravity matter? |
| `extrapolation` | Does a model trained on gravity 4–15 work at 2, 20 or 25? |
| `damping` | Does joint friction that varies between clips hurt, and does telling the model fix it? |
| `context` | Do 2–5 past states help, and when? |
| `nuisance` | Does the model ignore meaningless random inputs, or learn from them? |
| `systems` | Spring chains, cart-poles and bouncing balls compared to the hanging pendulum at the same state size |
| `dimension` | Growing the state from D = 16 to 128: separate pendulums vs 4-link chains |
| `scaling` | D = 16 to 1024 with one flat network vs one shared network per unit (pendulum or chain) |
| `training` | 60, 300 and 1000 epochs, with validation curves recorded during training |
| `training_arch` | 60, 300 and 1000 epochs, flat vs per unit, at D = 16 to 1024 |
| `parameters` | Every pendulum gets its own rod length and mass: which must the model be told, which can it work out? |
| `noise` | Size of the flow-matching start noise, and noise on the input states during training |
| `ground_params` | Ground pendulums with different rods: does telling lengths and masses help with the floor? |

Each variant is defined once in `experiments/plan.py` and trained once per
seed, even when several experiments compare it. A plain-language walkthrough
of the code is in [`experiments/README.md`](experiments/README.md).
