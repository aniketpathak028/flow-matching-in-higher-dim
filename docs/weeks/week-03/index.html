Telling the model each pendulum's length and mass

Every pendulum gets its own rod length (0.2–0.45 m) and mass (0.5–2×). Hinge height and light direction cannot change the motion, so they were not tested.

Validation loss during training · different rods: not told told · dotted: equal rods (reference)

* per unit, not told: it sees the last 3 states instead, to work the rods out.

8 pendulums with different rods (flat network)
  • Telling the length and mass helps when the network can match each value to its pendulum: always for per unit, and for the flat network only with a few pendulums.
  • The flat network can't make use of them at high D. With a few pendulums telling helps; with many it is just a long list of extra numbers it cannot match to the right pendulum, and it gets worse.
  • Not told, the per-unit network can work them out from the last few states, but its longer predictions drift more. So when the values are known, tell them.

Ground pendulums: telling the rod lengths

8 pendulums falling onto a floor (D = 16). Does knowing each rod's length and mass stop predicted rods from sinking into the floor?

Rods of different lengths and masses: not told told

Rods of different length on the floor
  • No, telling the length and mass does not help. Told or not, the model learns equally well and pushes rods into the floor just as often.
  • So missing information is not why rods sink. Last week all rods had the same length, so the model could already learn it from the data.
  • The real problem is the floor itself: the network does not learn the sudden stop when a rod hits the ground, and once its prediction is slightly in the floor, it keeps sinking.

Summary

  1. In our experiments, flow matching over the full state gets worse as D grows, while many small flows (per unit) stay accurate. Making the flat network wider or training it longer does not fix it. Whether this is caused by flow matching itself or by the network and data size is the next thing to test.
  2. Splitting the state into small pieces does. The per-unit network runs many small flows (one per pendulum) through one shared network and stays accurate up to D = 1024.
  3. Independent parts are easy, coupled parts are hard. At the same D, chains of linked pendulums are much less accurate than separate pendulums.
  4. Telling the length and mass helps when the network can match each value to its pendulum: always for per unit, and for the flat network only with a few pendulums.
  5. On the floor, telling the length and mass does not help: the rods still sink. The model has not learned the floor itself.

Next: flow matching in higher dimensions

  • A true high-dimensional flow with structure. Keep one shared per-pendulum network, but let every pendulum see the others' noisy points during the flow (attention or a graph network). Test it on pendulums that affect each other (joined by springs), where the problem cannot be split.
  • Flow matching vs plain regression at high D. Same networks, but predicting the answer directly. Shows whether the flat network fails because of flow matching or because of the network.
  • Flow in a smaller space. Compress the 1024 numbers into a few dozen (an autoencoder) and run flow matching there, as image generators do.
  • How many flow steps does high D need? 1, 5, 20 or 50 steps from noise to answer, at D = 16 and 1024: accuracy against prediction cost.
  • Straighter flows. Pair each noise sample with its closest answer (optimal-transport pairing) so the paths cross less in high D; this should need fewer steps.
  • Where flow matching should win: uncertain motion. Add random pushes to the pendulums, so the future is a spread, not a single answer. Check whether the high-dimensional flow reproduces that spread, which plain regression cannot.
